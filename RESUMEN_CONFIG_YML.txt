✅ PASO 5: ENTENDER CADA JOB
════════════════════════════════════════════════════════════════════════

Estructura de un job:

┌─────────────────────────────┐
│ checkout_and_build:         │
│   docker:                   │ ← Imagen Docker
│     - image: cimg/base      │
│   environment:              │ ← Variables de entorno
│     APP_NAME: "mi-app"      │
│   steps:                    │ ← Pasos a ejecutar
│     - checkout              │   (descargar código)
│     - run:                  │   (ejecutar comando)
│         name: "Build"       │
│         command: |          │
│           echo "Compilando" │
│     - persist_to_workspace: │ ← Guardar archivos
│         root: .             │
│         paths:              │
│           - .               │
└─────────────────────────────┘


✅ PASO 6: ENTENDER EL WORKFLOW
════════════════════════════════════════════════════════════════════════

El workflow define el ORDEN:

  pipeline_principal:
    jobs:
      - checkout_and_build        ← Job 1 (primero)

      - unit_tests:               ← Job 2a
          requires:
            - checkout_and_build  ← Requiere que Job 1 termine

      - integration_tests:        ← Job 2b
          requires:
            - checkout_and_build  ← Requiere que Job 1 termine

      - deploy_production:        ← Job 3a
          requires:
            - unit_tests          ← Requiere que Job 2a y 2b terminen
            - integration_tests
          filters:
            branches:
              only: main          ← SOLO si rama = main

      - deploy_development:       ← Job 3b
          requires:
            - unit_tests
            - integration_tests
          filters:
            branches:
              only: develop       ← SOLO si rama = develop

      - report:                   ← Job 4 (final)
          requires:
            - unit_tests
            - integration_tests


✅ PASO 7: ENTENDER EL FLUJO DE EJECUCIÓN
════════════════════════════════════════════════════════════════════════

Cuando haces: git push origin main

FLUJO:
  1. checkout_and_build (2-3s)
     │
     ├─→ unit_tests (1-2s) ─┐
     │                       ├─→ deploy_production (3-5s)
     └─→ integration_tests   │
         (3-4s) ────────────┤
                             └─→ report (1s)

TOTAL: 15-25 segundos

¿Por qué es rápido?
• unit_tests e integration_tests corren EN PARALELO
• No espera a que uno termine para empezar el otro
