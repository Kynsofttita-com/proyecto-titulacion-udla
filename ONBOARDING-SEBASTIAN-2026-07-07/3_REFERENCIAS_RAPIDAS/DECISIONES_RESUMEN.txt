§ 2 — BASE DE DATOS: 1 PostgreSQL, 9 SCHEMAS
================================================================================

Decisión: Una sola BD compartida, pero 9 schemas separados (uno por MS)

Para ti:
  - MS-Notificaciones: schema "notificaciones_schema"
  - MS-Reportes: schema "reportes_schema"
  - Datos de otros MS (estudiantes, instructores, etc.) están en otros schemas
  - NO hay FKs entre schemas (evita acoplamiento)
  - Consistencia = eventual (vía eventos RabbitMQ)

Migraciones:
  - Tus migraciones van en backend/ms-notificaciones/src/main/resources/db/migration/V*.sql
  - Flyway las ejecuta automáticamente al arrancar

================================================================================
§ 3 — MESSAGING: RABBITMQ
================================================================================

Decisión: RabbitMQ para eventos asíncronos (no Kafka)

Para Sprint 12 (Tarea 1.2 - Listeners):
  - Tu MS-Notificaciones **escucha** eventos de dominio
  - Cuando llega un evento, envías un email
  - Si falla, reintentás (máx 3 veces)
  - Si sigue fallando, va a DLQ (Dead Letter Queue)

Eventos que escucharás:
  - EstudianteMatriculado (desde MS-Estudiantes)
  - PagoRecibido (desde MS-Cobros)
  - ClaseAsignada (desde MS-Asignaciones)

Cómo funciona:
  1. MS-Estudiantes publica evento en exchange "eventos_domain"
  2. RabbitMQ lo enruta a cola "notificaciones.estudiante-matriculado"
  3. Tu listener lo consume
  4. Genera email y lo envía por Mailtrap/Gmail

URL para ver colas:
  http://localhost:15672 (guest/guest)

§ 6 — MAPEO DTO ↔ ENTITY: MAPSTRUCT
================================================================================

Decisión: MapStruct para evitar boilerplate

Para ti:
  ```java
  @Mapper(componentModel = "spring")
  public interface PlantillaEmailMapper {
    PlantillaEmailResponse toResponse(PlantillaEmail entity);
    PlantillaEmail toEntity(PlantillaEmailRequest request);
  }

  // En Service:
  private PlantillaEmailMapper mapper;

  public PlantillaEmailResponse crear(PlantillaEmailRequest request) {
    PlantillaEmail entity = mapper.toEntity(request);
    PlantillaEmail saved = repo.save(entity);
    return mapper.toResponse(saved);
  }
  ```

§ 7 — EXCEPTION HANDLING: RFC 7807 (ProblemDetail)
================================================================================

Decisión: Todas las excepciones retornan ProblemDetail (estándar REST)

Para ti:
  ```java
  @ExceptionHandler(PlantillaNotFound.class)
  public ResponseEntity<ProblemDetail> handlePlantillaNotFound(
      PlantillaNotFound ex, HttpServletRequest request) {
    ProblemDetail pd = ProblemDetail.forStatusAndDetail(
      HttpStatus.NOT_FOUND,
      ex.getMessage()
    );
    pd.setInstance(URI.create(request.getRequestURI()));
    return ResponseEntity.status(HttpStatus.NOT_FOUND).body(pd);
  }
  ```

Ya hay un GlobalExceptionHandler, solo agregás tus excepciones custom.

§ 10 — LOGGING: SLF4J + LOGBACK
================================================================================

Decisión: SLF4J (simple facade), Logback implementación

Para ti:
  ```java
  private static final Logger log = LoggerFactory.getLogger(PlantillaEmailService.class);

  public PlantillaEmailResponse crear(PlantillaEmailRequest request) {
    log.info("Creando plantilla: {}", request.getNombre());
    try {
      PlantillaEmail entity = mapper.toEntity(request);
      PlantillaEmail saved = repo.save(entity);
      log.debug("Plantilla creada con ID: {}", saved.getId());
      return mapper.toResponse(saved);
    } catch (Exception ex) {
      log.error("Error creando plantilla", ex);
      throw new PlantillaEmailException(ex.getMessage());
    }
  }
  ```

Niveles:
  - DEBUG: Información detallada (variables, valores)
  - INFO: Punto de referencia (inicio de proceso, éxito)
  - WARN: Algo inusual pero no crítico
  - ERROR: Error que se puede recuperar

§ 23 — SISTEMA DE NOTIFICACIONES: MULTI-CANAL

Decisión: Email (síncrono inicial) + In-app (async RabbitMQ)

Para ti:
  - Listener RabbitMQ recibe evento
  - Busca plantilla de email
  - Reemplaza placeholders ({nombre}, {email}, {fecha})
  - Envía por Mailtrap (dev) / Gmail (prod)
  - Crea registro en tabla "notificaciones" (in-app)
  - Si hay error, reintentá y va a DLQ

Flujo:
  EstudianteMatriculado
    ↓
  RabbitMQ → Cola notificaciones.estudiante-matriculado
    ↓
  Listener PlantillaEmailListener
    ↓
  EmailService.enviar(PlantillaEmail)
    ↓
  Mailtrap SMTP (dev) / Gmail (prod)

Base de datos:
  - plantillas_email: nombre, asunto, contenido
  - notificaciones: usuario_id, tipo, mensaje, leida_at
  - logs: para auditoría de envíos
